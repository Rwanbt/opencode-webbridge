# G19 — Témoin externe facultatif contre rollback du journal

La signature HMAC du journal G6/G15 garantit l'intégrité, **pas la fraîcheur**. La restauration d'une ancienne copie intacte, déjà signée, pouvait faire disparaître un tour `leased` puis permettre sa nouvelle exécution. Le test G19 reproduit exactement cet état historique, sans accès à un navigateur réel.

`DurableRelayJournal.open(dir, binding, secret, { witnessDir })` active un **mode strict version 2** : les transitions enregistrent dans un répertoire distinct un compteur et la MAC courante, protégés eux-mêmes par HMAC-SHA256. Le témoin est avancé et synchronisé **avant** le journal : si le processus tombe entre les deux renommages, le désaccord bloque le redémarrage, jamais un nouveau tour. L'initialisation d'un journal ancien sans témoin est refusée, tout comme l'ouverture ultérieure d'un journal protégé sans la configuration `witnessDir` (prévention du downgrade). Les prompts, réponses, secrets et cookies ne sont pas persistés dans le témoin.

**Condition de sécurité :** le témoin doit résider sur un stockage séparément administré et protégé contre l'écriture ou la restauration par l'adversaire capable de manipuler le journal. Deux répertoires accessibles au même attaquant ne procurent **pas** une défense forte : restaurer les **deux** anciennes copies valides demeure possible. Le code n'est pas une preuve matérielle d'anti-rollback, et l'absence d'un compteur monotone externe matériel/OS reste un blocage pour une garantie générale.

**Disponibilité :** le mode témoin est opt-in et n'est pas encore branché dans les smokes OpenCode : ces derniers restent en mode journal v1 pour compatibilité des fixtures. Un déploiement exige de provisionner la séparation de confiance, conserver la même clé de signature, sauvegarder le témoin, et définir une procédure de récupération **manuelle et attestée**. Il n'y a ni récupération silencieuse ni réparation automatique d'un désaccord. Sur Windows la synchronisation du répertoire par `fsync` n'est pas disponible, comme pour G6.

Tests déterministes : rollback d'une copie encore correctement signée, témoin corrompu, refus d'enrôlement implicite, séparation de répertoires, réouverture sans témoin et configuration vide. Exécuter `npm test` et `npm run typecheck`. Le résultat est un durcissement ciblé, pas la certification d'un service commercial.
