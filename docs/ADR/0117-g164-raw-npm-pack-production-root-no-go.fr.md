# ADR 0117 — G164 : distribution npm brute de la vraie racine OpenCode WebBridge

**Décision :** réparer le paquet brut, sans staging de sortie ni modification de l'application OpenCode. Base exacte G163 #242, SHA `e8c896ebdd6c374c03e46217671a920716cab95b`, en worktree isolé. Sur cette base, la CI PR `39085176972` était verte mais la CI push `39085172156` était rouge : ne pas les présenter comme deux validations réussies.

**RED reproduit :** `npm pack --dry-run --ignore-scripts --json` de la source G163 emballait 278 fichiers dont `src/**/*.ts`, mais **aucun** `dist/src/index.js` alors que `package.json#main` y renvoyait. La cause était `.gitignore:dist/` en l'absence de liste `files` et de compilation `prepack`. Le test G164 reproduit également ce négatif sur une copie **source seule** ; `--ignore-scripts` ne permet volontairement pas de fabriquer un paquet fonctionnel et doit échouer aux gardes de contenu.

**GREEN :** `npm pack` normal appelle exclusivement `scripts/g164-prepare-package.mjs`, qui refuse un répertoire de sortie symbolique, vide un ancien `dist` et compile l'entrée réelle `src/index.ts` avec `tsconfig.pack.json`. TypeScript suit ses imports transitifs ; `files: ['index.mjs','dist/src/',...]` inclut le code exécutable et les déclarations, jamais les sources TypeScript, secrets, tests ni fixtures. Le CLI officiel ne chargeait pas le paquet brut avec seulement `main=dist/src/index.js` (inventaire natif vide) : le véritable `index.mjs` désormais **inclus dans le tarball** réexporte l'entrypoint compilé, sans aucun wrapper construit dans un staging temporaire. `@opencode/plugin@2.0.29`, `effect@4.0.1` et `playwright@1.64.1` sont des dépendances d'exécution publiées avec le manifeste, et non des dépendances dev absentes du tarball. La licence et les notices restent incluses. `private:true` empêche volontairement toute publication accidentelle au registre ; on peut installer le **tarball local** sans compilation manuelle.

La CI G164 sous Linux utilise `@opencode/cli@2.0.32` officiel **dans un arbre temporaire**. Elle exécute `npm pack` depuis le dépôt, puis depuis une copie de la **source TS sans dist** où seul le numéro de version est mis à jour. Elle installe successivement `0.0.0 → 0.0.1 → 0.0.0` par `npm install <archive.tgz> --prefix <temp>`, sans wrapper `index.mjs`, manipulation de l'archive, copie manuelle de `dist` ou recompilation de l'application officielle. À chaque version, le CLI natif est démarré avec son profil isolé, son plugin chargé **par URL de répertoire de paquet**, et son option CDP personnelle lecture seule active ; le test impose `opencode.webbridge` en état `active`, vérifie son module réel et interdit toute publicité fictive de cinq modèles commerciaux. Le retour arrière vérifie le hash original de l'entrypoint.

**Garde-fous :** aucun effet sur `src/index.ts`, G158/G163, l'application installée, `main` ou le dépôt amont. Pas d'authentification ChatGPT réelle, pas d'attestation Desktop/OS, pas de modèle inférence utilisable, aucune écriture commerciale. Les preuves sont celles d'un **plugin externe réellement distribuable/chargeable**, sans prétendre lever les portes de production : 0/5 fournisseurs opérationnels, 0/54 stories acceptées, écritures OFF, **NO-GO-PRODUCTION**.
