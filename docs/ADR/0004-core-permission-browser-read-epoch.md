# ADR 0004 — Core-owned browser read permission epoch (follow-up to #110)

**Status: Draft, read-only reference; native Desktop effects NOT authorized.** Source: official OpenCode V2 exact `4617210822bdbb31e5749751afbfb4584ccedac8`; patch is replayable. This worktree branches directly from #110 and does not edit the parent, official repository or Unifia.

## New enforceable Core contract

The real `Permission.Service` now owns `browserRead`, a `BrowserLease` instance, rather than accepting a caller-supplied `authorize` predicate as its authority. `issue` uses the actual `Permission.Service.assert` path twice: `browser:*` and an exact `browser_plugin` resource containing plugin ID/generation, **`snapshot.once` only**, workspace, session, agent (in the `agent` request field), assistant turn, tool call, Desktop connection, tab and tab generation. It verifies `SessionStore` workspace identity; it never sets `save` resources, never registers new tools and **explicitly refuses** `click`/`fill`/`submit`/other actions. This reference does not claim plugin ID or turn values are authenticated: its binding argument still comes from the caller.

`BrowserLease` still reserves before awaiting consent, burns even unsuccessful consumed tickets, prevents replay across revoke, enforces TTL and validates live identity. `Permission.Service` owns the lease epoch and retires it on close. `reply(reject)` and synchronous durable Bus projection of `Session.Permissions`, `Session.AgentSelected`, `Session.Moved`, and `Session.Deleted` revoke outstanding and pending grants. Agent State exposes a synchronous `revision()`, and saved permissions increment their revision before and after DB mutation. The authority compares both versions synchronously **during issue and consume** and invalidates on mismatch. A RED test found that the original `BrowserLease` compared epochs *before* calling `live()` and could consume a revoked grant; the epoch comparison now runs after `live()` in both issue and consume.

Independent E2 follow-up to #114: real `PluginHooks.register("permission", "evaluate", ...)` could change a decision from allow to deny after issuing a read ticket without changing the Core lease epoch. Likewise, `Agent.Service.get` returned its internal mutable policy object, allowing a caller to bypass State revision via `Object.assign`. Both were reproduced against the original #114 patch with local Bun regressions. The fixed reference tracks permission-hook registration/removal via a synchronous revision in `PluginHooks.Service`; Agent's public getters now return detached snapshots, leaving legitimate policy mutations to `State.transform`. Tests cover hook addition, disposal, and direct mutation of a returned agent object, with the existing agent and permission suites preserved.

## Strict scope and remaining gaps

This is a **Core-only reference API**. Neither `ctx.browser.snapshotOnce`, `BrowserConnection`, the Desktop `experimental.browser.command` IPC nor Chromium executes through `Permission.Service.browserRead` yet. There is no Desktop host commitment, receipt, authenticated untrusted-plugin boundary, durable distributed epoch, or proof of revocation between browser command retrieval and the actual DOM effect. Direct database writes or other out-of-band policy mutations bypass the service revisions; a permission-hook callback can alter a captured mutable closure without re-registering, which also cannot be detected by hook-registry revision. A general saved `allow` may satisfy `assert`, so this is not proof of interactive consent for every read. The optional Interface properties preserve third-party Core test doubles; real services implement them. Binding values for plugin/agent/turn still lack Core-attested caller provenance. None of this enables native writes, external services or account access.

**Tests and no-go:** Real Permission.Service integration tests cover denied/allowed rules, precise prompt resource, consent revoked during await, actual durable session policy change, agent transform, saved-permission writes, one-shot consume, forged workspace and rejection of writes. Tests only invoke local Core fixtures; no Desktop/browser provider is launched. Moving to native effects requires authenticated server-to-Desktop issue+commit+consume and synchronized mutation epochs, independently reviewed with offline page fixtures. Do not merge as a complete transactional browser authority.
