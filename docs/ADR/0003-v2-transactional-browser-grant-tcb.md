# ADR 0003 — Native V2 browser grant authority and Desktop commit boundary

**Status:** Proposed, security review required. **No runtime browser permission or write action is activated.**

**Source freeze:** official `anomalyco/opencode` V2 commit `4617210822bdbb31e5749751afbfb4584ccedac8`. Stacked on the read-only [PR #95](https://github.com/Rwanbt/opencode-webbridge/pull/95), which itself builds on #84. This repository stores an upstream patch proposal only; the OpenCode upstream and Unifia repositories are unchanged.

## Verified current boundaries

`packages/core/src/permission.ts`: `Permission.Service.assert` evaluates agent/session/saved rules and optional user approval. Its return is `void`, **not** a revision-bound decision or a one-use grant. `reply` and policy changes have no common atomic epoch/consumption operation. Rechecking twice can still race an asynchronous permission or policy mutation.

`packages/plugin-browser/src/connection.ts`: server holds an attachment map and queues commands by request ID. The Desktop requests `experimental.browser.command`; the reply contains only the plain `Browser.Command` (`action`, `generation`, `files`, `inspect`, `target`). `packages/gui-extensions/src/browser/pane.ts` receives it asynchronously and later calls `execute`; `chromium.ts` executes the action. **There is no authenticated grant or consumption receipt at the Desktop execution boundary.** A server-side consume at RPC retrieval cannot revoke a command already returned to Desktop. Navigation/click/submit can be irreversible; on disconnection after commit, outcome is **unknown**, not rolled back.

## Increment: local Core lease contract (not wired to browser dispatch)

`packages/core/src/plugin/browser-lease.ts` implements an **unexported-to-plugin, per-instance reference ledger** for review. It binds *exactly* plugin ID and generation, agent, session, workspace, assistant turn, tool-call, Desktop connection ID, tab ID + generation, and exact action. A trusted injected `live(binding)` rechecks current authority. `issue` reserves the complete binding before awaiting injected authorization, detects an intervening `revoke()` epoch change, times out the authorization and refuses duplicate issue. Tickets are random, ephemeral and consumed synchronously at most once. `consume` burns the ticket on mismatch, timeout or retired generation; no retry or second ticket for the same committed binding in the epoch. `revoke` invalidates outstanding tickets and in-flight issuances; `retire` permanently closes the coordinator.

The test harness makes `authorize` and `live` deterministic. This **does not integrate with** `Permission.Service`, session-policy mutation events, the Desktop RPC protocol or the Chromium action executor. A future implementer cannot treat the ledger's `revoke()` as automatic policy revocation until every authoritative permission mutation is serialized with it. Its injected `live` callback cannot be satisfied by client/plugin claims. Same-process malicious JavaScript plugins are not isolated by TypeScript module privacy. No writable tool is exposed by this patch.

## Required TCB before any native write

1. Core Permission authority must own a monotonically increasing **decision epoch**. Changes to session/agent/project permissions, policy hooks, consent withdrawal, expiration, interruption, plugin retirement and workspace moves must synchronously advance the relevant epoch (not via a later, asynchronously delivered event). Permission evaluation and lease reservation must revalidate the same revision after any await. Explicit `ask` consent must be for the precise operation; saved or general browser permission cannot substitute for write consent.
2. Trusted Tool/Agent executor must attest the real session, current assistant turn, tool call and caller plugin generation, not take these identities from mutable plugin arguments. Pin the trusted built-in browser driver and the live Desktop connection/tab generation. Bind the grant to a single normalized action and local test-page origin (for testing). No credentials, headers, cookies or page text in grant metadata or logs.
3. Extend versioned browser RPC **and Desktop execution TCB together**, with a grant reference opaque to untrusted plugins. Desktop must authenticate its window, tab, attachment and target document; validate the exact envelope, and perform one authoritative `commit/consume` handshake immediately before effect. The **commit** is the linearization point: once committed, further revocation prevents *new* actions but cannot unwind that effect. A duplicate or stale grant receives a refusal. Merely adding a `grantID` to `Browser.Command` does not provide a security check.
4. Close/disconnect **before commit** invalidates the lease. Disconnect/timeout **after commit** is recorded as *possibly executed / unknown outcome*, never silently retried or rolled back. Preserve an append-only decision/effect receipt and force reconciliation for uncertain writes. If strict stop-after-revocation is required even between a network response and DOM execution, remote RPC is insufficient: serialize the actual effect with revocation inside the same trusted Desktop process and define its commit ordering explicitly.
5. Adversarial gate must exercise real Desktop IPC on an **offline local HTML fixture only**: withdrawal between consent/commit, concurrent double-fetch, forged plugin/agent identity, cross-workspace/tab/window, reload/disconnect, timeout and uncertain result; deny network destinations other than loopback. No commercial provider calls. Keep read-only Code Mode behavior compatible.

**Decision:** Accept this small, testable *Core-only* contract as a review artifact. Do **not** claim the `Permission.Service.assert` race or Desktop execution gap is closed in production, and do **not** enable native writes, until items 1–5 are implemented and independently reviewed. Previous PR #95 `snapshotOnce` remains a bounded read-dispatch proof, not a Desktop-authorized transaction.
