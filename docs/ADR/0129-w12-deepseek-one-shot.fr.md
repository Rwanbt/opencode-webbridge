# ADR 0129 — W12 : envoi DeepSeek explicite, unique, état incertain

**Base** : PR #281, HEAD `63782993cf23cb877bdd9b83921cf32c5f73dbf2`. Nouveau worktree indépendant. W12 n'est pas branché sur le registre de modèles, le plugin racine ni l'installation officielle.

`w12SendDeepSeekOnce` cible exclusivement un onglet Chromium choisi par l'opérateur sur `https://chat.deepseek.com`, relié au `Target.getTargetInfo.targetId` et revalidé via l'inventaire G155 et l'epoch CDP `frameID/loaderID/URL` (G161). Le prompt exact est présenté par `approveSend` avec la liaison `sessionID/turnID/tabID/generation/URL/SHA256`; `isStillApproved` est une autorisation synchrone révocable, le `signal` peut annuler l'opération. Les sélecteurs du compositeur/bouton sont **des candidats synthétiques à vérifier sur DeepSeek authentifié**. Tout élément manquant, dupliqué, caché, toute rédaction humaine existante, navigation, révocation ou refus stoppe l'envoi.

Le journal durable `g159ConsumeOnce` est partagé avec G159 : un même identifiant de tour est consommé exclusivement une fois, avant le remplissage et le clic, par un marqueur `O_EXCL` avec synchronisation disque dans le dossier privé fourni par l'hôte. Le cast TypeScript vers le type d'action G159 est limité à cet appel ; au runtime le `actionHash` est celui de l'action DeepSeek réelle. Pas de prompt brut, cookie, identifiant ou mot de passe dans le journal. Après consommation, tout échec devient `W12_SEND_UNCERTAIN`; tout clic unique retourne `status: uncertain` : le DOM ne prouve aucune acceptation ou fin de réponse fournisseur.

**Qualification** : CI Linux, un Chromium en profil temporaire avec interception HTTPS `chat.deepseek.com`, approbation positive, refus, brouillon concurrent, bouton dupliqué, révocation après saisie, anti-rejeu, rechargement même URL et navigation adverse. Aucun accès au service commercial, aucun secret ou compte utilisateur. Le test est uniquement une preuve du contrôle d'effet local.

**Limites** : confiance dans la déclaration du propriétaire du port CDP sans attestation système ; impossibilité d'atomicité entre le dernier contrôle de révocation et le clic UI ; absence de preuve de finalité, de sélecteurs validés en réel et de consentement certifié Desktop. Le registre préexistant garde DeepSeek `sendPrimitive: null`. **NO-GO production, aucune inférence DeepSeek par ce patch et aucune écriture activée par défaut.**
