# ADR 0009 — Refus des lectures natives héritées sans autorité Core

**Problème.** Les correctifs G38/G52/G56/G57 protègent l'opération exacte `snapshot` via `Permission.Service.browserRead`, `BrowserLease` et `read.commit`, mais la surface officielle `experimental.browser` accepte aussi `frames`, `find`, `evaluate`, `screenshot`, `network.get`, `console`, `files.get`, les captures heap/CPU/trace et `tabs.list`. `BrowserConnection.target.request` pouvait encore les lancer sans ticket de lecture Core et `pane.ts` laissait passer leur IPC sans commit. Certaines réponses incluent contenus, cookies indirects, en-têtes, URLs, éléments de page ou fichiers de capture.

**Décision fail-closed.** Dans le patch rejouable épinglé `4617210822bdbb31e5749751afbfb4584ccedac8`, la connexion navigateur refuse `request` et `inspect` pour toute opération hors d'une allowlist stricte d'**effets historiques déjà contrôlés séparément par les permissions OpenCode**, sauf `snapshotOnce` explicitement autorisé. La GUI impose la même allowlist avant d'exécuter une commande reçue directement par IPC. Même un ticket `snapshot` ne peut pas déverrouiller une autre action. Toute nouvelle opération native inconnue est refusée tant qu'elle n'a pas été classifiée. La liste explicite s'applique à `tabs.list` : titres/URLs sont des métadonnées sensibles, donc cette ancienne énumération est temporairement indisponible.

**Preuve RED → GREEN.** Sur le vrai `read-commit-gate.ts` du patch épinglé, un harness Bun adversarial appelait `desktopReadCommitGate` pour `frames`, `find`, `evaluate`, `screenshot`, `network.get`, `console` et `files.get` sans ticket. **RED avant :** `AssertionError: unsafe direct IPC: frames` (`true !== false`). **GREEN après :** `GREEN: historic direct browser reads denied without native Core read receipt`. Des tests Bun officiels ajoutés vérifient également le refus de `target.inspect()` et `.request([])` pour `find`, `evaluate` et `network.get`, l'absence d'émission RPC, le refus d'IPC direct et la parité complète des allowlists serveur/GUI pour chaque action actuelle. Patch complet reconstitué et `git apply --check`, application puis reverse-check réussis sur un second checkout officiel indépendant.

**Compatibilité volontairement limitée.** Ce changement bloque aussi des outils de lecture *officiels* du navigateur OpenCode (notamment `tabs.list`, `find`, `evaluate`, captures, profiling), faute de preuve d'une autorité transactionnelle pour eux. Il ne prétend pas offrir leur remplacement; **ne pas proposer ce patch tel quel en amont** sans API Core liée à chaque action et tests d'usage/UX. Les effets historiques autorisés par ailleurs ne deviennent pas des effets WebBridge : son contrat `ctx.browser` ne donne aucun droit d'écriture et toute donnée issue du navigateur est non fiable.

**NO-GO persistant.** Aucun mécanisme atomique Core ↔ Desktop ↔ Chromium, aucun verrou sur les révocations de politiques entre processus, aucune attestation IPC cryptographique, aucune couverture E2E Electron réelle. Les opérations `navigate/click/fill/submit` WebBridge et les cinq adaptateurs commerciaux restent désactivés. Aucun merge/upstream distant/Unifia.
