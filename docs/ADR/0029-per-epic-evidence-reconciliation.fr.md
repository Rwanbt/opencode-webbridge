# ADR 0029 — Réconciliation des preuves de PR avec les neuf épics

Ce rapport de planification **n'est pas une checklist d'acceptation**. Les PR Draft #142–#162 ont été observées vertes sur leurs SHA exacts, dont les incréments d'octobre #155–#162. Le nombre de checks enregistré est le minimum directement attesté lors de l'observation ; GitHub peut ajouter des runs supplémentaires sur la même tête sans transformer ces assertions en acceptation production. La PR #163, dont deux jobs de packaging sont encore en échec au moment de cette révision, est délibérément **absente** jusqu'à correction et contrôle du nouveau SHA.

`planning/progress.json` relie chaque épic E0–E8 à ses six stories réelles du backlog et aux PR qui fournissent un sous-ensemble de preuves : gouvernance E0, runtime modèle de fixture E1, browser/attachement E2, transport conversation E3, sécurité E4, cinq contrats d'adaptateurs hors ligne E5, métadonnées/UI locale E6, permission de propositions et quotas workers E7, CI/gates E8. Un défaut bloquant substantiel est explicitement conservé pour chaque épic. Il y a **zéro story acceptée** dans chaque groupe.

Le garde CI vérifie désormais toutes les 21 PR listées (#142–#162 sans saut), la correspondance des IDs d'épic et cardinalités, l'existence d'une preuve référencée et l'absence de promotion en production. Les tests négatifs mutent une story, une PR référencée ou un statut d'acceptation, et doivent être refusés. Cette validation est hors ligne et ne télécharge pas GitHub; le relevé des SHA/CI a été vérifié avant édition. Aucun fichier upstream/OpenCode Desktop n'est modifié, aucune PR fusionnée, et les cinq fournisseurs restent 0/5 opérationnels.
