# ADR 0086 — G135 / T02 : exécution lecture seule, **fixture uniquement**

**Décision : expérimental / NO-GO production et privilèges Core.** Base exacte PR #210 (`41b642225860272cf39e73037aed6e20b7262a78`). Ce lot ne modifie ni G133 `tool-proposal.ts`, ni les adaptateurs E5/G134, ni le patch natif G132, ni la CI, ni une application officielle.

Le nouveau `createOfflineReadonlyExecutor` n'admet qu'une racine canonique **sous le répertoire temporaire du runner**, des propositions `validateToolProposal` détachées et gelées, et une fonction d'autorisation asynchrone **fournie indépendamment par le host** (réponse `true` obligatoire, refus des retours absents). Elle est rappelée avant/après chaque effet, abort compris. Aucun retour n'est livré si la permission est retirée pendant l'attente. Pas de commande terminal, shell, navigateur, réseau, modification Git, fournisseur distant ou grant produit ici. Les résultats sont bornés (16 KiB max), UTF‑8 et gelés ; les sorties contenant des marqueurs de secrets et certaines formes d'échappement sont **refusées** plutôt que transmises. Ce contrôle rudimentaire **n'est pas une DLP exhaustive**.

Sur **Linux seulement**, `file.read` vérifie la racine et chaque composant via `lstat`/`realpath`, refuse liens symboliques, accès `.git`, liens physiques (`nlink != 1`), ouvre la feuille `O_NOFOLLOW`, confronte inode/dev et `/proc/self/fd`, puis recoupe chemin et métadonnées après la lecture et après la seconde autorisation. Les courses de renommage et révocations sont exercées sur un véritable dossier temporaire. Il n'y a néanmoins **aucun appel `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)`** : la protection contre toute course hostile entre composants n'est **pas formellement garantie**. Sur **Windows `file.read` échoue systématiquement**, faute d'API de confinement de handle/reparse équivalente dans Node.

`git.status`, `git.log` et `git.diff` exercent de vraies commandes **sur le dépôt temporaire exclusivement**, avec argumentaire statique, `spawn(shell:false)`, `--no-optional-locks`, `GIT_OPTIONAL_LOCKS=0`, configuration globale/système désactivée, fsmonitor et diff externe neutralisés, délai et volume stdout bornés. `.git` doit être un vrai répertoire interne non symbolique ; `git.diff` path-scopé rejette les chemins non réguliers/alias. Les tests confirment notamment la non-mutation de l'index par les lectures. **Ce processus Git n'est pas un sandbox OS** : un dépôt/configuration hostile, ses objets/attributs, les courses de renommage et la sélection de l'exécutable Git nécessitent encore une politique et isolation système fiables. Aucun effet shell arbitraire n'est revendiqué.

Tests de vraie FS/Git : lecture confinée Linux et refus explicite Windows ; symlink externe parent/feuille, alias hardlink, remplacement après lecture, refus d'autorisation avant/après, scope/provenance corrompus, action inconnue/mutable, secrets et sorties encodées, limite de taille, interruption incertaine. Les tests sont découverts automatiquement par `npm test` **dans le job Linux `checks`**. Sans modifier la CI partagée (hors propriété G135), le job Windows existant compile le nouveau source et ses tests mais ne les exécute pas ; l'exécution ciblée est faite localement sous Windows. Cela ne vaut pas attestation d'intégration dans le Core ou Desktop.

**Périmètre produit inchangé : 0/5 fournisseurs commerciaux, 0 acceptation, écritures navigateur OFF, NO-GO.** Pour une sortie de fixture, il faudrait un broker natif attestation/permission/secret, un confinement OS résistant aux TOCTOU, un contrôle de provenance pour la racine/Git et une politique de divulgation réelle. Aucun merge/upstream/main/Unifia/OS local ne découle de cette ADR.
