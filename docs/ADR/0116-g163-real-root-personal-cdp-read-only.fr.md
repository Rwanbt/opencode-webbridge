# ADR 0116 — G163 : vraie extension racine opt-in, préparation CDP personnelle

**Décision : activer les lectures CDP dans le vrai plugin racine, PAS cinq modèles fictifs.** Base exacte PR #240 `413bb53a0e399f8f0a1b7c8470323e6448405404`. Aucune modification de l'application OpenCode officielle, de l'upstream, du profil utilisateur ou des autres branches.

Dans le SDK public `@opencode/plugin@2.0.29`, `ctx.provider.transform` permet de déclarer une source de modèles et `ctx.aisdk.hook('language')` peut modifier le transport. **Cela ne constitue pas une passerelle d'inférence**, ni une preuve d'autorisation d'envoi. Les adaptateurs CDP G157/G160 ne font qu'observer du texte et **ne prouvent jamais la fin du flux**. La branche G159, non incluse dans la base gelée, fournit une tentative d'envoi à consentement par action, mais retourne elle-même `uncertain`, pas une acceptation du fournisseur ; aucun service de consentement humain permanent ni attestation Desktop/OS ne sont disponibles au chargement de la racine. Déclarer des modèles « fonctionnels » sur la seule présence d'un onglet fabriquerait donc un faux positif dangereux.

**Capacité concrète :** lorsque l'utilisateur fournit explicitement `WEBBRIDGE_PERSONAL_CDP_READONLY=1`, `WEBBRIDGE_PERSONAL_BROWSER_OWNED=1`, `WEBBRIDGE_PERSONAL_CDP_ENDPOINT=http://127.0.0.1:<port>`, le vrai `src/index.ts` enregistre un outil natif OpenCode `webbridge_browser`. Ses actions `list` et `headings` utilisent la découverte CDP G155 et le protocole WebSocket natif, sans Playwright requis. Les cinq origines officielles sont filtrées. `list` ne révèle que le fournisseur et l'identifiant d'onglet, jamais les chemins/queries d'URL. `headings` retourne une liste bornée de titres, sans valeurs de formulaire/cookies. L'action `read` exploite G157 pour ChatGPT et G160 pour DeepSeek/Gemini/Mistral si le module Playwright est présent dans l'environnement ; **Qwen reste sans parseur fiable**. Chacune des opérations requiert `ctx.permission.assert` avec la session native et la cible ; une révocation/fermeture/navigation échoue fermé. Le propriétaire du port CDP est **déclaré par l'utilisateur**, sans preuve du principal OS.

Le plugin ne se connecte à aucun port par défaut, ne lance aucun navigateur, n'inspecte aucune session sans consentement, n'envoie aucun prompt, n'extrait aucun secret et n'enregistre **aucun modèle commercial**. Les règles propres à chaque service et l'approbation explicite de chaque envoi restent indispensables à la future intégration de G159 ; aucune interdiction globale arbitraire de tous les services n'est ajoutée.

Tests : activation native du **vrai arbre JavaScript `dist/src` émis par TypeScript**, copié sans altération dans un répertoire de distribution temporaire, muni d'un simple `index.mjs` réexportant exclusivement la vraie entrée compilée (contrat `main` G143), puis empaqueté par `npm pack` et installé dans un profil isolé CLI officiel 2.0.32 ; vérification de son état actif et absence de modèles web fallacieux. Le `npm pack` du dépôt de développement exclut actuellement `dist/` à cause de `.gitignore` : une future livraison publique doit résoudre explicitement son manifeste/sa construction, **elle n'est pas prouvée par ce staging CI**. Chrome CDP réel avec interception **HTML local synthétique** à l'origine exacte ChatGPT pour découverte, titres, lecture et révocation ; refus du port hors `127.0.0.1`, de cible incertaine et de Qwen non vérifié. Pas de preuve d'authentification cinq sites, pas de mode Live commercial, pas de certification Electron Desktop. **NO-GO production et 0/5 opérés sont maintenus.**
