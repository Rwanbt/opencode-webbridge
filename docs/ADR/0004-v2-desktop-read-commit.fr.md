# ADR 0004 — Commit ponctuel Desktop limité à `snapshot`

**Statut : prototype de lecture, pas d'autorisation transactionnelle pour les écritures.** Base upstream officielle figée `4617210822bdbb31e5749751afbfb4584ccedac8`, PR empilée sur #110. Aucun code des dépôts upstream ou Unifia n'est modifié directement.

`bindSnapshot` fournit désormais une fermeture `read()` à usage unique. Le serveur `BrowserConnection` associe au `requestID` un ticket aléatoire expirant après cinq secondes, l'attachement de session, la connexion Desktop, l'onglet et sa génération. Le ticket n'est inclus que dans la commande `snapshot` de ce chemin, jamais dans `navigate`, `click`, `fill` ou `submit`. Le Desktop appelle `read.commit` avant la lecture et revérifie son entrée, sa fenêtre et la génération locale de l'onglet **avant et après** cet appel. Le serveur brûle toute tentative de commit, y compris un ticket forgé ; seule la première correspondance exacte est acceptée. Une réponse arrivée sans commit réussi **ou après remplacement de l'onglet** est refusée. Le simple `requestOnce` ne permet aucun nouveau type d'action.

Les tests adversariaux couvrent double consommation, ticket forgé, réponse sans commit, reconnexion de pilote, mutation de génération avant et après commit et refus d'émettre ce ticket pour `navigate`. `smoke:local-read` exerce une **vraie page de chat factice** sur `127.0.0.1` avec Chromium et bloque les URLs extérieures ; le test préexistant `smoke:page` ajoute le parcours OpenCode natif→RPC→compagnon. Ce sont deux validations E2E locales séparées, **pas** une certification d'IPC GUI Electron ni un test bout en bout de ce nouveau commit Desktop. Le `smoke:page` a encore reproduit localement sous Windows l'ancien délai `native run timed out` sur la branche de base, sans invalider le smoke Chromium indépendant ; la CI hébergée reste nécessaire pour statuer sur le parcours natif.

**Limites de sécurité importantes :** `Permission.Service.assert` n'expose toujours pas d'époque transactionnelle, le flux BrowserLease de #110 n'est toujours pas relié à la politique autoritative, et le Desktop est un pair déjà authentifié mais pas une preuve distante d'exécution honnête. Une révocation entre l'accusé de commit et la lecture ne peut être annulée ; seul `snapshot` est concerné ici. L'API RPC reste version 4 ; un Desktop plus ancien peut tenter une lecture avant de connaître le ticket mais le serveur refuse son résultat non acquitté. Un crash après commit laisse une issue inconnue, pas un résultat réessayable ; les tombstones de ce flux sont uniquement en mémoire. Les mutations ne doivent **jamais** réutiliser ce schéma : il faut l'epoch Permission, une autorité locale d'exécution sérialisée avec la révocation, les reçus durables et une revue E2 indépendante avant toute activation des écritures. Les sites commerciaux sont exclus.
