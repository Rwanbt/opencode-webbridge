# ADR 0025 — Témoin de journal requis pour le relais RPC OpenCode hors ligne

Le mode de test `webbridge-browser-fixture` chargeait le journal durable mais **n'utilisait jamais le témoin indépendant** de G73 : une restauration d'un ancien `journal.json` HMAC valide aurait échappé au contrôle dans les smokes réels du serveur OpenCode. Le plugin RPC de fixture exige désormais `WEBBRIDGE_RELAY_WITNESS_DIR` et l'utilise lors de `DurableRelayJournal.open`. Le répertoire témoin doit être indépendant du journal; le plugin refuse d'enregistrer ses routes RPC si ce prérequis manque ou que les chemins sont imbriqués.

Les scripts `smoke:rpc`, `smoke:e2e`, `smoke:page` créent un témoin dans un **second répertoire temporaire** avec clé aléatoire de test; `smoke:rpc` confirme aussi que le MAC du témoin correspond au journal effectivement réglé, puis efface les deux répertoires lors du nettoyage. Un test négatif du plugin démontre que l'absence de témoin ou la réutilisation du même répertoire empêche l'enregistrement des appels RPC. Les conditions commerciales ne sont jamais sollicitées.

Ce raccordement reste **strictement de test** : `src/index.ts` de production n'active aucun fournisseur. Deux fichiers restaurés ensemble peuvent encore tromper le témoin (absence de compteur monotone externe). Les environnements OpenCode officiels Electron/Desktop n'ont toujours pas été qualifiés de bout en bout ; aucune garantie atomique entre Core et Chromium, ni autorité de writes WebBridge n'est conférée. 0/5 fournisseurs commerciaux opérationnels, 0 production acceptée, aucune fusion.
