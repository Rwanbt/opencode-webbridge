# ADR 0107 — G156 : premier observateur DOM d'onglet ChatGPT attaché

**Statut : chemin de lecture implémenté, test Chromium local, NO-GO activation commerciale.** Base PR #232 `77b2711a745d1b9d79e6a1e0bc0fa7209ae0a582`. Aucun fichier du composant natif, de politique fournisseur ou de découverte de session n'est modifié.

Le module `src/providers/g156-chatgpt-dom.ts` accepte un *onglet déjà attaché par l'hôte* : `current()` fournit ID d'onglet, génération et URL ; `authorizeRead()` provient du contrôle indépendant hôte/Core ; `evaluate()` évalue seulement le lecteur DOM fixe. Le module n'effectue ni navigation, requête, capture de cookie, saisie, clic, login, ni écriture. Les cinq origines officielles HTTPS strictes proviennent du catalogue : ChatGPT `chatgpt.com`, DeepSeek `chat.deepseek.com`, Gemini `gemini.google.com`, Qwen `chat.qwen.ai`, Mistral `chat.mistral.ai`. **Seul ChatGPT a ici un parseur**, et le dispatch des quatre autres refuse.

Le parseur prend seulement la dernière réponse ChatGPT avec ID stable, corps `.markdown` (ancienne UI) ou `[data-markdown-text-style="assistant-message"]` (UI Chat/Work avec unités `:assistant`). Il ne sélectionne pas les bulles `:user` ni les blocs de raisonnement hors du corps. L'utilisateur/hôte désigne explicitement la clé du message ; tout changement de clé, réécriture sans préfixe, disparition, navigation, génération d'onglet ou révocation pendant l'attente échoue fermé. Le suivi émet des fragments textuels bornés (16 000 caractères, 4 096 par delta), jusqu'à 32 observations. **Aucun `finished` n'est fabriqué** : la fin générative ne peut pas être attestée par cette seule lecture DOM.

Vérification publique du 18 octobre 2026 : `https://chatgpt.com` est accessible en mode déconnecté ; DeepSeek renvoie 403 au client de recherche, Gemini expose une connexion, Qwen une page de compatibilité, Mistral redirige vers `/chat` avec connexion. Pour ChatGPT, la bascule UI Chat/Work décrite publiquement le 25 septembre 2026 retire certains attributs legacy et introduit `data-turn-key` / `data-content-search-unit-key`. Références : https://github.com/steipete/oracle/issues/517 ; https://github.com/JoonJ14/ai-conversation-navigator/blob/main/DOM-REFERENCE.md .

Tests : origine correcte des cinq domaines et faux domaines, getters/accessors refusés, permissions révoquées pendant les await, identités changeantes, sélection fixe, delta strict ; **vrai Chromium local** avec origine HTTPS *interceptée vers du HTML synthétique* pour les deux variantes UI, sans contacter les comptes commerciaux. Les CI Linux et Windows qualifient le contrat ; Linux rejoue également le HTML dans Chromium.

**Limite** : une interface `G156Attachment` transmise par l'hôte n'est pas une preuve d'identité OS/IPC ou d'autorisation Core effective. Aucun site connecté n'a été lu et aucun résultat authentifié cinq fournisseurs n'a été vérifié. Il manque l'attachement Desktop de confiance, la décision par opération, le binding réel de la session et la fin de flux authentifiée. Conservés : 0/5 opérationnels, 0/54 acceptés, aucun droit d'écriture et NO-GO production.
