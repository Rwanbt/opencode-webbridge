## Coexistence CI, pas même processus

Sur **un seul SHA de cette PR**, conserver les **sept** jobs d'origine G136 : `checks` + exécution Linux de la vraie FS/Git G135, `Windows bounded RPC` avec G133/G136 tests exacts et vérifications G135 fail-closed Windows, `upstream-v2-browser-patch` dans **un checkout officiel éphémère patché** (types et tests G106/G126/G131), `g125` et `g130` dans **la CLI originale distribuée `@opencode/cli@2.0.32` non patchée**, plus D01 CLI et 2.0.29 Chromium smoke. Le job G130 utilise une `.tgz` unique, DOM localhost, RPC, SSE, accusé durable chiffré et redémarrage du CLI ; ce host de test **n'est pas le Core**. Les jobs G125 et G130 refusent un faux ou absent `finish:'stop'` et son contenu attendu, permettent seulement des relectures bornées de l'API persistante officielle, et vérifient encore les sessions après redémarrage indépendant. Les scénarios de panne sont réellement négatifs et ne permettent aucun succès implicite.

Ces tests attestent la **coexistence sur le même commit WebBridge**, **pas** l'application du patch Core dans le processus officiel CLI, ni une validation d'Electron empaqueté, ni l'identification OS du pair de l'IPC. Les fixtures `verify:true` de native Core ne valent pas attestation. `read.live` et l'effet Chromium ne sont pas transactionnels entre processus. Aucun changement des sources provider E5/G134 n'est autorisé.

**NO-GO 0/5/0**, écritures WebBridge OFF, aucun fournisseur commercial activé, aucun merge/upstream/app officiel, aucune acceptation production.
