# ADR 0125 — G169 : Qwen CDP vérifié, réponse DOM non attestée en production

**Décision : NO-GO pour lire le texte d'une vraie conversation Qwen tant que sa structure DOM actuelle n'est pas indépendamment certifiée.** Base exclusive G166 #245 `4cd5ab9b1f6dd6cec5bd5f718d00671aaea945e0`. Les CI initiales G166 push `39087240112` et PR `39087242810` ont échoué dans le job G155/G160, avant G169 ; ne jamais les qualifier de succès.

`G169QwenRead.attach(endpoint, tabID, consent)` se raccorde à **un onglet Chromium existant** uniquement après déclaration de propriété du navigateur, consentement de découverte, signal d'annulation et accord synchrone révocable. Endpoint CDP limité au littéral `127.0.0.1`, cible vérifiée par ID CDP, origine HTTPS exacte `https://chat.qwen.ai`, URL complète, génération d'inventaire et `frameID/loaderID` `Page.getFrameTree` pour détecter même un rechargement à URL identique. Après chaque attente/asynchronisme : revérification d'identité, d'origine, de document, d'annulation et de révocation. Aucun lancement de Chromium personnel, saisie, cookie, token, écriture, envoi ou attestation OS/Desktop.

`probe()` est **exécutable sur la vraie interface** mais retourne uniquement `documentBound:true`, `liveSiteSelectorsVerified:false` et `NO_GO_UNVERIFIED_LIVE_QWEN_DOM`, jamais le texte de la page ou une fausse disponibilité de modèle. `sample(messageKey)` refuse catégoriquement hors `G169_INTERCEPTED_FIXTURE=1`, drapeau réservé à une fixture locale. Sous ce drapeau, un lecteur DOM fixe et auditable n'accepte qu'un conteneur `data-webbridge-g169-fixture=intercepted-qwen-v1`, un unique article assistant avec ID sélectionné et un unique corps direct sans champ/raisonnement/utilisateur imbriqué ; pas de fallback général `body.innerText`, d'index instable ou de sélecteur prétendument vérifié sur le site Qwen de 2026. Même avec ce drapeau, cette structure ne constitue **aucune preuve d'authenticité fournisseur**.

Le job Linux démarre un seul profil Chromium temporaire ; il intercepte `https://chat.qwen.ai` avec du HTML factice sans compte ni trafic commercial. Cas positifs/négatifs : cible Qwen exacte, probe sans contenu, fixture assistant identifié, refus du champ mot de passe/prompt/raisonnement, ID ambigu ou absent, permission refusée, annulation pendant attente, navigation à origine étrangère et reload `loaderID` changé sous URL identique. Aucun Chrome supplémentaire sur Windows.

**Intégration :** ce module n'est pas branché au plugin distribué ou à un modèle Qwen. Le G160 existant continue à refuser Qwen ; aucune CI héritée n'est masquée. `commercialProvidersOperational=[]` (0/5), `productionAcceptedStoryIDs=[]` (0/54), écritures OFF, `nativeDesktopElectronE2E=false`. **NO-GO production**.
