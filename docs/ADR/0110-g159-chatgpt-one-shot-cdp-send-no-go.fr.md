# ADR 0110 — G159 : envoi UI ChatGPT autorisé individuellement, one-shot, incertain

**Décision :** chemin d'envoi CDP **fonctionnel sur page Chromium factice**, pas une validation sur le site ChatGPT authentifié ni un contrat OS/Desktop de production. Base exacte de G157 #236 `651d1b12dc2fe5add48db798e6f548dca634efa4` dans un worktree indépendant ; aucun fichier G157/G158, plugin racine, application officielle ou dépôt amont modifié.

`g159SendChatgptOnce(request)` utilise le transport G155 pour vérifier l'endpoint explicite `127.0.0.1`, le consentement de découverte et l'identité/génération/URL d'un onglet `https://chatgpt.com` existant. CDP Playwright est relié au **target ID exact**, jamais à un onglet choisi implicitement. La fonction accepte uniquement un compositeur unique (`#prompt-textarea` contenteditable/textarea ou textbox `data-testid=composer-input`) et un bouton d'envoi unique (`data-testid=send-button` ou labels accessibles explicites). Ces sélecteurs sont **des candidats à vérifier sur le site réel de 2026**, pas des assertions d'une compatibilité vivante ; l'absence ou l'ambiguïté refuse tout effet. L'input utilisateur non vide n'est pas écrasé.

L'opérateur doit approuver **chaque action précise** contenant `sessionID`, `turnID`, `tabID`, `generation`, URL et SHA-256 du prompt (le prompt brut n'est pas dans l'approbation ni le journal). Une vérification synchrone révocable `isStillApproved` est répétée avant et après les attentes, conjointement à l'ID CDP, URL et `loaderId` de la frame. Une entrée exclusive `O_EXCL`, écrite puis `fsync` dans un dossier privé fourni par l'hôte, **consomme le tour avant le premier remplissage**. Même une coupure ou révocation après ce point laisse le tour **incertain** et interdit un nouvel essai automatique. Le clic est unique ; un retour `status: uncertain` **ne signifie pas** que le service ChatGPT a accepté la requête.

Les tests Linux utilisent un **seul Chromium neuf en profil temporaire**, une page `https://chatgpt.com` interceptée **localement**, et un faux compositeur/bouton : refus avant autorisation sans remplissage, clic unique après accord, journal antirejeu, cible ambiguë refusée, révocation après remplissage, navigation durant l'approbation. Aucun compte, cookie, secret, contournement d'authentification/CAPTCHA, authentification commerciale ou appel au vrai service n'est testé. Windows ne lance aucun Chromium.

**Limites bloquantes :** `approveSend` est l'interface vers une future UI de consentement fiable, pas une attestation de l'identité OS ; le client CDP peut agir dans une session déjà ouverte avec des privilèges élevés. Le port user-déclaré n'a pas de propriétaire OS attesté. L'automatisation d'un vrai ChatGPT requiert approbation utilisateur au moment de l'effet, sélecteurs validés sur le DOM actuel, contrôle de session Core/OS et preuves de finalité fournisseur. Aucune fusion ni activation dans `src/index.ts` ; **0/5 fournisseurs opérationnels, 0/54 stories acceptées, navigateur writes OFF dans le plugin distribué, NO-GO production**.
